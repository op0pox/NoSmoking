# 금연존 지킴이 — 기능 명세서

> 현재 구현된 기능과 각 기능을 그렇게 설계한 이유를 정리한 문서. 하드웨어 파일럿 계획은
> 교수님 피드백으로 보류 중이며, 지금은 `docs/개발-로드맵-소프트웨어데모.md` 기준
> 노트북에서 완결되는 소프트웨어 데모를 목표로 한다.

## 1. 설계 원칙

프로젝트 전체를 관통하는 원칙 3가지. 아래 개별 기능들의 "왜 이렇게 만들었나"는 대부분 이 세
원칙 중 하나로 설명된다.

| 원칙 | 내용 | 근거 |
|---|---|---|
| **영상 무저장** | 프레임은 추론 직후 메모리에서 폐기. 저장·전송·녹화 코드를 만들지 않는다 | 개인정보보호법 제25조(고정형 영상정보처리기기) 대응, 프로젝트 차별점 |
| **정밀도 우선** | 비흡연자에게 방송이 나가는 오탐이 최악의 실패. 미탐(놓침)은 허용 | 목적이 계도이지 단속·처벌이 아님 |
| **표준 모델 구조 유지** | YOLOv8n 계열 네트워크 구조·레이어를 바꾸지 않음 | 향후 Hailo Model Zoo 컴파일 경로 확보(하드웨어 포팅 재개 시) |

## 2. 감지 파이프라인

```
사람+포즈 감지 → 1차 게이트(손-입 모션) → 2차 확인(담배/연기 객체) → 시간 필터 → 음성 안내
```

### 2.1 사람 + 포즈 감지

**기능**: YOLOv8n-pose로 프레임마다 사람 박스와 COCO 17 keypoints를 다중 인물 추출하고,
ByteTrack으로 사람별 track id를 부여해 프레임 간 동일 인물을 유지한다.

**왜 이렇게 했나**:
- 별도의 "사람 감지" 모델을 두지 않았다 — 포즈 모델이 사람 박스를 함께 출력하므로 모델 하나를
  아낄 수 있다(엣지 디바이스 연산 절감).
- MediaPipe Pose가 아니라 YOLOv8n-pose를 썼다 — MediaPipe는 단일 인물 추정에 최적화돼 있어
  현장(여러 명이 동시에 있을 수 있는 금연구역)에는 맞지 않는다.
- 트래킹을 붙인 이유는 사람별로 독립적인 상태(아래 2.2~2.4)를 유지하기 위함이다. 트래커는
  ByteTrack을 명시적으로 고정했는데, 일부 ultralytics 버전의 기본 트래커는 새 track 생성
  임계값이 너무 높아(new_track_thresh 0.7 등) 웹캠의 일반적인 포즈 신뢰도로는 track id가
  아예 배정되지 않는 문제가 있었다.

**구현**: `edge/motion_detector.py`

### 2.2 1차 게이트 — 손-입 반복 모션 감지

**기능**: 손목-입(코 좌표를 보정해서 추정) 사이 거리를 어깨너비로 정규화해, 이 거리가
임계값 미만으로 일정 시간 유지됐다가 벌어지는 걸 "puff(한 모금)"로 카운트한다. 60초 윈도
안에 3회 이상 puff가 쌓이면 그 사람을 `SMOKING_SUSPECTED`로 전환한다.

**왜 이렇게 했나**:
- 담배 객체 인식(2차 확인)을 모든 사람·모든 프레임에 상시 돌리면 연산 낭비가 크고, 오탐
  위험도 커진다. 학습이 필요 없는 저비용 규칙 기반 필터로 먼저 "의심 후보"를 좁혀서 2차
  모델은 필요할 때만 돌린다.
- 규칙 기반이라 라벨링된 데이터가 부족한 프로젝트 초기 단계에도 바로 쓸 수 있었다.
- 손-입 반복 동작은 연초·전자담배(아이코스 등) 공통이라 기기 종류를 가리지 않고 잡을 수
  있다.
- 입 keypoint가 COCO 17개 중에 없어서, 코 좌표를 어깨너비 대비 일정 비율만큼 아래로 보정해
  입 위치로 대신 쓴다(`MOUTH_OFFSET_RATIO`).
- 임계값(`NEAR_THRESHOLD` 등)은 실측 기반으로 잡았다 — 주먹 쥐고 무는 동작과 손가락 사이에
  끼우는 동작은 손목-입 거리가 실제로 다르게 나온다(핀치 그립은 손 길이만큼 거리가 더
  있음). 1차 게이트는 recall(재현율) 우선으로 넉넉하게 잡고, 정밀도는 2차 확인과 시간
  필터에서 확보하는 쪽으로 역할을 나눴다.

**구현**: `edge/motion_detector.py` — `SmokingMotionDetector` 클래스

**주요 파라미터**: `NEAR_THRESHOLD`(0.6), `MIN_HOLD_SEC`(1.0s), `MAX_HOLD_SEC`(6.0s),
`WINDOW_SEC`(60s), `MIN_PUFFS`(3회), `WRIST_CONF_THRESHOLD`(0.15 — 손목 keypoint는 활발히
움직이는 중에도 신뢰도가 낮게 나와 몸통용 임계값(0.5)과 분리)

### 2.3 2차 확인 — 담배/연기 객체 감지

**기능**: `SMOKING_SUSPECTED`로 판정된 사람에 한해서만, 그 사람의 bbox를 크롭해 커스텀
YOLOv8n(cigarette=0, smoke=1) 모델을 돌린다. 모션 점수(puff 누적 정도)와 2차 모델 신뢰도를
가중합해 combined 점수를 낸다.

**왜 이렇게 했나**:
- 모션만으로는 통화, 음료 마시기, 안경 고쳐쓰기 같은 손-얼굴 동작과 구분이 안 된다. 실제
  담배/연기 객체가 있는지 확인해야 정밀도가 확보된다.
- 상시 실행이 아니라 의심 구간에만 실행하는 이유는 엣지 디바이스(라즈베리파이) 연산 제약을
  고려한 것 — 무거운 객체 감지 모델을 매 프레임 모든 사람에게 돌리면 목표 FPS(10, 마지노선
  5)를 못 맞출 위험이 있다.
- 프레임 전체가 아니라 사람 bbox로 크롭해서 추론한다 — 실측 결과 담배 같은 작은 객체는
  전체 프레임 기준으로는 해상도가 너무 낮아 거의 검출이 안 됐는데, 사람 영역만 잘라서 돌리니
  검출률이 크게 개선됐다.

**구현**: `edge/cigarette_detector.py` — `CigaretteDetector` 클래스

**현재 한계**: v1 모델(`cigarette-v1-best.pt`)은 재라벨링 진행 중이던 스냅샷(약 200장)으로
학습해 mAP50 ~0.3, precision 변동이 크다. 재라벨링이 약 500장으로 진행되면서 v2 재학습을
준비 중이다(관련 이슈 #20).

### 2.4 시간 필터

**기능**: 최근 10초 슬라이딩 윈도 안에서, combined 점수가 임계값 이상인 프레임의 비율이
60% 이상일 때만 "이벤트"를 확정한다. 최소 10초 이상 관측되기 전에는 확정될 수 없다(표본
1~2개로 순간 확정되는 것 방지).

**왜 이렇게 했나**:
- 한 프레임의 순간적인 오탐(각도·블러로 그 프레임만 잘못 잡힌 경우 등)으로 바로 이벤트가
  확정되면 정밀도 우선 원칙에 어긋난다. 지속적인 신호일 때만 확정하도록 시간 축에서 한 번 더
  걸러낸다.
- 확정 상태는 래칭되지 않는다 — 비율이 다시 떨어지면 미확정으로 돌아간다. "안내 방송을
  울릴지" 같은 후속 판단은 이 필터의 책임이 아니라 음성 상태 머신(2.5)에 넘긴다.

**구현**: `edge/event_filter.py` — `EventTimeFilter` 클래스

### 2.5 음성 안내 상태 머신

**기능**: 이벤트가 확정되면 1차 완곡 안내 mp3를 재생한다. 30초가 지난 시점에도 여전히
이벤트가 확정 중이면 2차(법적 고지 포함) 안내를 재생하고, 아니면 조용히 쿨다운으로
넘어간다. 쿨다운 중에는 재확정돼도 무시해 중복 방송을 막는다.

**왜 이렇게 했나**:
- 프로젝트 목적이 계도이지 단속·처벌이 아니라서, 처음부터 강한 경고를 주지 않고 완곡한
  안내 → (지속 시) 법적 고지 순으로 단계를 나눴다.
- 마이크(녹음) 관련 코드는 아예 만들지 않았다 — 실시간 TTS도 안 쓰고 사전 녹음된 mp3만
  재생한다. 오디오 입력 자체가 법적으로 금지된 영역이라 설계에서 원천 배제했다.
- 재생은 외부 파이썬 오디오 라이브러리(playsound, pygame 등) 없이 OS 기본 플레이어를
  논블로킹 subprocess로 실행한다 — 의존성을 가볍게 유지하기 위함(향후 파이 포팅 고려).

**구현**: `edge/voice_announcer.py` — `VoiceAnnouncer` 클래스

## 3. 테스트/개발 지원 기능

### 3.1 영상 파일 재생 모드 (`--source`)

**기능**: 웹캠 실시간 입력 외에, 저장된 영상 파일을 재생하며 동일한 파이프라인을 그대로
돌릴 수 있다(`--source webcam` 또는 `--source 영상경로.mp4`).

**왜 이렇게 했나**: 5주차 오탐 튜닝(함정 동작 벤치마크)을 하려면 같은 시나리오를 반복
테스트할 수 있어야 하는데, 매번 실제로 동작을 재연하는 건 비효율적이다. 원래
`docs/개발-로드맵-소프트웨어데모.md` 6주차 계획에 있던 기능을 튜닝 필요 때문에 앞당겼다.
영상 파일은 처리 속도가 실시간과 다를 수 있어 시간 기준을 영상 자체의 재생 위치
(`CAP_PROP_POS_MSEC`)로 잡아, 처리 속도와 무관하게 시간 임계값이 영상 속 실제 경과 시간과
맞도록 했다.

### 3.2 포즈 추론 해상도 조정 (`--pose-imgsz`)

**기능**: 포즈 모델 추론 해상도(imgsz)를 조정할 수 있다. 기본값은 640(웹캠 근접 촬영
기준).

**왜 이렇게 했나**: 설치 예정 거리를 흉내 낸 테스트 영상(전신이 작게 나옴)에서 실제
흡연 동작이 있었는데도 전혀 감지되지 않는 문제가 있었다. 원인을 프레임 단위로 분석한 결과
모델이나 임계값이 아니라 추론 해상도였다 — 기본 640은 1920x1080 원본을 3배 가까이 축소해서
보는 셈이라 멀리 있는 사람의 keypoint(특히 손목) 정보가 거의 소실됐다. 해상도를 1920까지
올리자 같은 영상에서 puff 감지부터 이벤트 확정, 안내 재생까지 파이프라인이 정상 동작했다.

## 4. 데이터 설계

### 4.1 클래스 통합 (cigarette / smoke)

**기능**: 학습 데이터 클래스를 `cigarette`(일반 담배 + 전자담배 기기 통합)와
`smoke`(담배 연기 + 전자담배 에어로졸 통합) 2개로 잡는다.

**왜 이렇게 했나**: 설치 환경에서 담배·전자담배 같은 객체가 약 10~30px 크기로 관측되는데,
이 크기에서는 두 유형을 안정적으로 구분하기 어렵다. 또한 최종 목표도 "무슨 기기인지
분류"가 아니라 "흡연 여부 판단"이라, 유형을 나누는 것보다 통합하는 게 목표에 더 맞는다.

### 4.2 부정 샘플(negative sample) 명시적 확보

**기능**: 음료를 마시는 사람, 통화하는 사람, 휴대전화를 얼굴 가까이 든 사람, 담배와 비슷한
소품(펜 등)을 든 사람 등을 라벨 없이 데이터셋에 포함한다.

**왜 이렇게 했나**: 정밀도 우선 원칙과 직결된다. 오탐을 줄이려면 "흡연처럼 보이지만
아닌" 상황을 모델이 학습 단계에서부터 접해야 한다.

### 4.3 자체 촬영 병행

**기능**: 공개 데이터셋(Roboflow) 외에 설치 예정 각도·높이·거리로 자체 촬영한 영상을
라벨링·데모용으로 함께 확보한다.

**왜 이렇게 했나**: 공개 데이터셋과 실제 설치 환경(카메라 거리·각도)의 도메인 갭이 실측으로
이미 확인됐다(3.2 참고 — 같은 모델도 촬영 거리에 따라 감지율이 크게 달라짐). 실제 환경과
가까운 데이터 없이는 정밀도·재현율을 신뢰하기 어렵다.

## 5. 보류된 기능

교수님 피드백으로 하드웨어 구매·현장 설치를 보류하고, 노트북에서 완결되는 소프트웨어
데모로 우선순위를 조정했다(`docs/개발-로드맵-소프트웨어데모.md` 참고). 아래 항목은 삭제가
아니라 "지금 안 하는 것"이며, 승인 시 이어갈 수 있도록 조사 자료를 남겨둔다.

- 라즈베리파이5 + Hailo AI Kit 포팅, IP 카메라, 방수 스피커·앰프
- 현장 설치, 섀도 모드 운영, 학교 승인·법정 안내판
- FastAPI 서버 연동, Streamlit 대시보드 (실치 없이는 우선순위 낮음)
